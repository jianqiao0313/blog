# Blog 性能优化执行计划

范围：补齐现有文章图片固有尺寸；修复文章导航重复监听；播放器接近视口时加载；停止 Pagefind 旧产物累积。不升级依赖，不改文章内容和视频索引结构。

1. 先用回归测试锁定每项缺陷：图片尺寸缺失、重复导航监听、屏外播放器提前加载和异步加载后的失效挂载、旧搜索索引混入新产物。
2. 图片：读取实际图片尺寸，保留 lazy/async 与响应式比例；避免每次构建都依赖远程图片服务。显式尺寸优先。
3. 文章脚本：使用明确的页面初始化/销毁生命周期，保留进度条、标题链接、复制按钮和灯箱；不重复注册全局监听。
4. 播放器：动态加载库和样式，接近视口时初始化，保留原生媒体可用性；导航时销毁观察器和播放器，过期异步任务不得挂载。
5. Pagefind：生成全新的生产索引，不再将旧 public 索引复制进 dist；保留开发搜索路径，重复构建的文件集稳定。
6. 分别验证后统一执行回归测试、Astro 检查、lint、格式检查和生产构建；用 browser-harness 测试站内导航、媒体和搜索。独立复核后提交、推送 main，并核对对应部署及线上结果。

实现分工：主任务负责图片、集成、浏览器测试与发布；三个独立子任务负责文章生命周期、播放器和 Pagefind。各自拥有独立文件及测试，避免交叉修改。


执行结果：四项修复和 24 项回归测试完成。浏览器验证了响应式图片、播放器延迟请求、导航监听数量稳定、生产与开发搜索；连续构建的 Pagefind 文件及内容一致。完整检查和独立复核通过，详细证据见 `../review-2026-09-17.md` 的“四项性能优化复验”。
